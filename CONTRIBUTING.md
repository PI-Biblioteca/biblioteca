# Contributing

## Fluxo de contribuição

1. Escolha uma Issue atribuída a você.
2. Crie uma branch a partir de `develop`.
3. Use um nome de branch relacionado à tarefa. Para a Entrega 1, priorize o prefixo `docs/`.
4. Faça somente alterações relacionadas à Issue.
5. Realize commits objetivos e descritivos.
6. Abra um Pull Request direcionado para `develop`.
7. Relacione a Issue ao Pull Request.
8. Aguarde a revisão.
9. O merge será realizado após a aprovação.

## Padrão de branches

- `docs/` — documentação e modelagem.
- `fix/` — correções.
- `feature/` — novas funcionalidades, quando entrarem no escopo de desenvolvimento.

Para a Entrega 1, o trabalho deve priorizar alterações de documentação e modelagem.

## Pull Requests

Todo Pull Request deve:

- estar relacionado a uma Issue;
- informar claramente o que foi alterado;
- conter somente alterações relacionadas à tarefa;
- ter como branch de destino `develop`;
- aguardar revisão antes do merge.

## Commits

Use mensagens objetivas e descritivas.

Exemplos:

- `docs: adiciona requisitos funcionais`
- `docs: atualiza modelagem da devolução`
- `docs: documenta cálculo da multa`

## Revisão

A revisão deve verificar se a alteração atende à Issue, mantém a organização do repositório e não introduz mudanças fora do escopo da tarefa.
